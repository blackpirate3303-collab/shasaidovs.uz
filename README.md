# Shasaidovs — GitHub Pages + Supabase

Готовый стартовый проект сайта с регистрацией, входом, ролями `admin` / `user`, меню на неделю, рецептами и админ-панелью.

## Состав проекта

- `index.html` — интерфейс и страницы.
- `css/style.css` — оформление и адаптивный дизайн.
- `js/config.js` — URL и публичный ключ проекта Supabase.
- `js/app.js` — авторизация, меню, рецепты, админ-панель.
- `supabase/schema.sql` — таблицы, RLS-политики, триггер регистрации и защищённые RPC-функции.

## 1. Создайте проект Supabase

1. Создайте проект на https://supabase.com/.
2. Откройте **Project Settings → API** (в новом интерфейсе это может называться **API Keys**).
3. Скопируйте **Project URL** и **Publishable key** (или legacy `anon` key).
4. Вставьте значения в `js/config.js`.

Пример:
```js
window.SHASAIDOVS_CONFIG = {
  SUPABASE_URL: "https://abcdefgh.supabase.co",
  SUPABASE_ANON_KEY: "sb_publishable_..."
};
```

**Никогда не публикуйте `service_role` или secret key в GitHub/JavaScript.** Публичный publishable/anon key допустим только вместе с правильно настроенными RLS-политиками.

## 2. Создайте таблицы и политики

1. В Supabase откройте **SQL Editor → New query**.
2. Скопируйте весь файл `supabase/schema.sql` в редактор.
3. Нажмите **Run** и убедитесь, что SQL завершился без ошибок.

Схема включает Row Level Security:
- пользователь читает и редактирует только своё меню;
- вошедшие пользователи читают общие рецепты;
- только администратор может управлять рецептами;
- список почт пользователей и изменение ролей доступны только через проверяемые серверные RPC-функции;
- пользователь не может назначить себе роль администратора через обычное обновление профиля.

## 3. Настройте регистрацию и подтверждение email

В Supabase откройте **Authentication → URL Configuration**:
- **Site URL**: адрес опубликованного GitHub Pages, например `https://USERNAME.github.io/REPOSITORY/`.
- Добавьте этот адрес в **Redirect URLs**.
- В **Authentication → Providers → Email** настройте подтверждение email по своему выбору. Если включено подтверждение, пользователь должен подтвердить почту прежде чем войти.

Для работы SMTP-писем в реальном использовании настройте собственный SMTP-провайдер в Supabase. Ограничения встроенной почты подходят в основном для тестирования.

## 4. Назначьте первый аккаунт администратором

1. Откройте сайт, зарегистрируйте свой аккаунт и подтвердите email, если требуется.
2. Войдите в Supabase → **SQL Editor**.
3. Выполните запрос, заменив email на свой настоящий адрес:

```sql
update public.profiles p
set role = 'admin'
from auth.users u
where p.id = u.id
  and lower(u.email) = lower('YOUR_EMAIL@example.com');
```

4. Проверьте, что обновлена ровно одна строка. Если 0 строк — аккаунт ещё не зарегистрирован/не подтверждён или email отличается.
5. Выйдите из сайта и войдите снова. Должна появиться вкладка **Администрирование**.

Не добавляйте в приложение функцию самоназначения администратора. Назначайте первого администратора только из доверенной панели Supabase.

## 5. Загрузите проект в GitHub Pages

В корне репозитория должны лежать именно эти файлы:
```text
index.html
css/style.css
js/config.js
js/app.js
supabase/schema.sql
README.md
```

1. Загрузите папки и файлы в репозиторий, не только `index.html`.
2. В GitHub откройте **Settings → Pages**.
3. Выберите публикацию из ветки `main` и папки `/ (root)` (или соответствующую папку, если разместили проект в ней).
4. Сохраните настройки и дождитесь публикации.
5. Откройте URL сайта и сделайте жёсткое обновление `Ctrl+F5`.

GitHub Pages — статический хостинг; серверную часть авторизации и базы данных предоставляет Supabase.

## Функции

- Регистрация и вход через Supabase Auth.
- Роли `user` и `admin`.
- Пользовательское меню на каждый день: завтрак, обед, ужин.
- Сохранение меню в облачную базу.
- Общая коллекция рецептов; добавлять/изменять/удалять рецепты может администратор.
- Админ-панель: список пользователей и управление их ролями.
- Список покупок хранится локально в браузере конкретного устройства.

## Важные замечания

- В браузерном коде используется только publishable/anon key. Никогда не используйте `service_role` key в `config.js`.
- Supabase RLS — обязательная часть безопасности. Не отключайте RLS и не добавляйте широкие политики `using (true)` для операций записи.
- Этот стартовый проект не реализует удаление аккаунтов из Auth, восстановление пароля, MFA, аудит админ-действий или полноценный серверный список покупок. Удаление аккаунтов Auth следует делать через защищённую Edge Function с проверкой роли, а не напрямую из браузера.
- Не храните в проекте секреты. Если ключ уже попал в публичный репозиторий и это secret/service-role key, немедленно отзовите/перегенерируйте его.
